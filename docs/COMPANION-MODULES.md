# Trip Mode, Booking Assistant, China SOS

Scope: extend the existing Shanghai MVP without accounts, payments, live location, live traffic, ticket sales, or a general AI support chatbot. Preserve the warm paper/olive/burgundy visual system. Use one prominent next-action surface in Trip Mode, a source-backed task list for bookings, and short step-by-step troubleshooting for SOS. Restrained status transitions and native modal Chinese cards honor reduced motion.

Trip Mode selects today's itinerary in Asia/Shanghai; other dates are explicitly previews. The next stop is the earliest planned, unfinished/unskipped stop, not a live arrival prediction. Each occurrence has an identity. Completion and skipping are undoable and persist locally; replanning, replacement, and time changes must not inherit stale completion. Chinese display opens in one tap. Navigation goes directly to Amap search with Chinese destination/address. Nearby alternatives are approximate straight-line distances from the planned stop, not the visitor's current location; no route/open-status guarantee.

Booking Assistant derives venue followups only for relevant stops. Museum details come from the operator; other ticket rules remain explicitly unverified. Every task shows source, passport/ID guidance, review date or UNKNOWN, and cautions. Train task is opt-in because the existing city itinerary contains no intercity trains. Hotel task accepts a Chinese address and an HTTPS operator link from the user, labeled unverified. No passport/booking reference collection. Confirmations mean user confirmation only; itinerary changes invalidate affected task confirmations. Clicking an external link never confirms a task.

SOS contains six focused locally bundled guides: payment declined, SMS, finding a place, train tickets, mobile data, and Chinese help. Each has concrete steps, a large Chinese explanation, an official reference where available, and an escalation route without a success guarantee. Users may mark a problem resolved; this is user-reported. No AI call or support-message transmission. Already loaded guidance can be read without connectivity; external links need internet.

Validation: domain tests for date boundaries, occurrence identity, skip/undo, next-stop order, alternatives, task derivation and confirmation invalidation. Existing tests/typecheck/build plus browser checks at 375, 390 and 1440 px for all three modules, persistence, Chinese dialog, booking distinctions, SOS steps/error/empty states. No remote mutation, push, production deployment, or paid calls authorized.
